# Abilities & effects

**Files:** `systems/ability_system/` (60 .gd, 3306 lines total; this doc covers the ability half). Key files: `ability.gd` (249), `ability_manager.gd` (143), `ability_database.gd` (53), `ability_effect.gd` (44), `ability_targeting.gd` (132), `ability_timing.gd` (38). 18 `AbilityEffect` subclasses (`*_effect.gd`), 7 targeting classes (`melee_enemy`, `ranged_enemy`, `ground_point`, `area`, `aerial_area` (extends area), `self`, `dismiss`), VFX/animation composition (`vfx_effect.gd`, 6 `*_step.gd`, `animation_sequence.gd`, `animation_phase.gd`, `magic_missile_projectile.gd/.tscn`). Data: `data/abilities/` (**19 .tres**). Execution lives in `systems/unit_system/unit_combat.gd:264-447` (owned by the Unit doc).
**Autoloads owned:** `AbilityManager` (`project.godot:23`).

## Purpose
Defines what an ability IS: a data-only `Ability` Resource composed of one targeting shape, an ordered list of effects, costs, optional timing, and cast/armed presentation (`ability.gd:22-150`). `AbilityManager` tracks the one "armed" ability for click-to-target (`ability_manager.gd:29-36`). `AbilityDatabase` resolves abilities by name for save/load and debug grant lists (`ability_database.gd:36`). NOT responsible for: executing an ability (to-hit roll, cost spending, effect loop are `UnitCombat.use_ability`, `unit_combat.gd:264-409`), status lifetime (see statuses.md), hotbar UI (`ui/ability_hotbar.gd`, `ui/hotbar_slot.gd`), AI choice (`systems/ai_system/`).

## Derived / cached state
- `AbilityDatabase._catalog` caches a one-time scan of `data/abilities/` (`ability_database.gd:52`); stale if a .tres is added at runtime without `refresh()` (`:43`).
- `Ability.indicator_ids()` / `get_pathed_projectile_step()` / `get_move_caster_effect()` are derived from composition at call time, not stored (`ability.gd:180-233`), so they cannot drift.
- `armed_unit` duplicates "who is commanded" (`PlayerInteractionState.get_active_unit()`, read at `ability_manager.gd:63,103`); it is only refreshed by `arm()`/`disarm()`, so it can disagree with the active unit (see Known issues 3).
- `Unit.abilities` / `custom_slots` (Unit doc) and `PartyMemberData.abilities` are copies of references to the shared .tres (`party_manager.gd:390-391,740-741`).

## Depends on
- `PlayerInteractionState.get_active_unit()` — `ability_manager.gd:63,103`.
- `Unit` API: `in_combat`, `has_attacked`, `has_move_remaining` (`ability.gd:249`, `ability_manager.gd:141`); `take_damage`, `heal`, `apply_status` from effects; DR is read only by `DamageResolver.injury` (`systems/combat_system/damage_resolver.gd`), which every damaging effect calls. Every damaging effect (and every `AttackRow`) carries a `wound_type` — the GURPS damage type, cr/cut/imp/pi-/pi/pi+/pi++/burn/cor/tox (B379) — whose torso wounding multiplier the resolver applies after DR, rounded down, min 1 if anything penetrates. A punch and a fall are crushing. An `armor_divisor` (B378) divides DR first, rounded down; fractional ones multiply it. An attack can instead be aimed at a `HitLocation` (`systems/combat_system/hit_location.gd`, `data/hit_locations/`) through an aim toggle (`UnitCombat.AIM_TOGGLES`: `target_vitals.tres` -3 x3 imp/pi only, `target_head.tres` -7 x4 +2 DR, not tox); the location's multiplier replaces the wound type's and its DR is added before the divisor. `UnitCombat.hit_location_for` falls back to the torso, without the penalty, for an attack the location doesn't take. Deceptive Attack (`UnitCombat.DECEPTIVE_ATTACK`, `data/abilities/deceptive_attack.tres`, B369) is a leveled toggle (`max_level` 5) every unit has: at level N, `to_hit_target` takes -2N on a to-hit attack against a Unit and `UnitCombat.defense_against` (used by both `hit_chance` and the defense roll) takes -N off the defender's best defense. No skill floor. The hotbar slot shows the level (dimmed while off); a left click while on steps 1→5→1, a left click while off turns it on at the kept level, a right click switches it off keeping the level. It combines with the aim toggles. Injury Tolerance (B380): a unit has one `InjuryPreset` (`data/injury_presets/`: Unliving, Homogeneous, Diffuse) plus independent `missing_locations` (No Vitals, No Brain), built over its `BodyPlan` by `InjuryProfile.build`. Not modelled: fatigue damage, corrosion's DR loss (e.g. `damage_effect.gd:20-21`, `heal_effect.gd:19`, `apply_status_effect.gd:19`).
- **Attack rows** (`systems/inventory_system/attack_row.gd`): one way to attack — label, kind (melee/ranged), sw/thr/fixed dice + bonus, wound type, divisor, reach. A weapon owns rows (`WeaponData.attacks`, e.g. the iron sword's Swing sw+2 cut / Thrust thr+2 imp); demons carry natural ones (`UnitDefinition.natural_attacks`, `data/attacks/` claws/fangs/horns). A `GearDamageEffect` with `row == null` is a template: `Unit.combat_abilities()` (`unit_combat.gd`) replaces each template with one bound copy per row of `attack_rows(kind)` — main-hand weapon, then natural attacks; melee with neither falls back to `PUNCH` (thr-1 cr). Held rows come from `ItemInstance.attacks()`, the copy's own rows: a rune's local `damage_bonus` and `AttackRow.to_hit_bonus` (added in `_hands_modifier`) live there, and the bound-copy cache keys on that per-copy row. The off-hand weapon's rows (`off_hand_rows`) are bound too, named "Swing (off hand)", with `GearDamageEffect.off_hand` set. Bound copies are cached per (template, row, hand) so identity is stable; reach comes from the row. **Hands** (`UnitCombat._hands_modifier`, added in `to_hit_target`): off hand -4 (B417, no Ambidexterity); `AttackRow.min_st` costs -1 per point of ST short (B270), against current ST, so Exhausted's halving counts. `WeaponData.two_handed` (e.g. `data/items/greatsword.tres`, sw+3/thr+3, reach 2, ST 12) is enforced by `UnitEquipment.hands_allow` (see inventory.md). **Shields** are weapons too: each carries a "Shield Bash" row (thr cr, reach 1) with `AttackRow.off_hand_ok`, bound without the off-hand flag, so no -4 and no suffix (GURPS Shield skill). Sizes: `buckler` DB 1, `wooden_shield` DB 2, `tower_shield` DB 3; DB adds to Dodge, Parry and Block (unit_combat.gd). `unit.abilities` and saves still hold templates. The hotbar and `AiScorer._damaging_abilities` read `combat_abilities()`; the hotbar rebuilds on `Unit.equipment_changed`. **Weapon sets:** holding a weapon is enough. A unit whose `abilities` lack a template for a kind it holds rows for (most PCs have only the melee one) gets that kind's shared template (`UnitCombat.DEFAULT_TEMPLATES`), so melee and ranged attacks are both on the bar at once and switching costs nothing. **Ranged rows** (`AttackRow` "Ranged" group, `data/items/longbow|crossbow|throwing_axe|pistol|rifle.tres`): `acc` is added when the shooter hasn't moved this turn (`_aim_bonus`; the stand-still is the GURPS Aim maneuver); `max_range` caps the bound copy's RangedEnemyTargeting; past `half_damage_range` the roll is halved (`AttackRow.is_past_half_damage`). Ranges are CRPG-sized, not the book's: every shot ½D 20 / Max 40, every throw ½D 10 / Max 20, in metres read as yards. Every ranged row also takes B550's range penalty (`UnitCombat.range_penalty`, in `to_hit_target` off the edge distance): 0 to 2, -1 at 3, -2 at 5, -3 at 7, -4 at 10, -5 at 15, -6 at 20, -7 at 30, -8 at 50; it is what keeps Acc and RoF from making long shots free. Spells are not ranged rows and take none. Bows set `weapon_st` and roll thr/sw from it, not the archer's ST; crossbows and guns use FIXED dice. A RANGED row on a melee-hand weapon (the throwing axe's "Throw") is offered with the ranged attacks and is never consumed. **Firearms:** `WeaponData.shots` is the magazine, `ItemInstance.fire/reload` spend and refill it (not saved; a loaded weapon comes back full); `Ability.out_of_ammo` disables the slot and the AI plan. `data/abilities/reload.tres` (`ReloadEffect`, one attack action, fills every held weapon) is appended while a magazine weapon is held. Its motion is the drawn gun's `WeaponData.reload_motion` (`&"reload.pistol|rifle|crossbow"`, which the humanoid MotionSet answers with `data/animation_sequences/weapon_reload_*.tres`): `UnitCombat._reload()` hands out a cached copy of reload.tres with that `motion`, so the turn is held through the clip; reload.tres itself plays none. `rof` adds B373's +1 at 5/9/13/17/25/50; on a hit with several shots, hits = min(shots, 1 + margin / recoil), and each hit meets DR separately (`GearDamageEffect.apply`); a successful defense removes 1 + its margin hits.
- `UnitCombat.DamageType` / `EquipSlot.Slot`. `AttackRow.DamageBase` shares `DamageType`'s SWING/THRUST values and passes them through as ints: naming UnitCombat's enum from a row would compile `unit_combat.gd` (and its const `.tres` preloads) while a row `.tres` loads, a cycle that failed `crit_fail_penalty.tres` and hung headless runs.
- `UnitQuery.area_affected` — `area_damage_effect.gd:49`, `area_heal_effect.gd:34`, `area_apply_status_effect.gd:35`.
- `NavigationGrid.nearest_valid_point` — `knockback_effect.gd:66`.

## Assumptions and invariants
- An `Ability` resource is shared and never mutated at runtime: no code assigns to Ability fields or appends to `effects` (grep of `systems/ ui/ world/` finds no writes). Required because one .tres is shared by many units (issue 5).
- `ability_name` is unique across `data/abilities/` — it is the save key (`ability_database.gd:36`, `party_manager.gd:508`). Not enforced; first file wins silently (`ability_database.gd:52` passes `find_first_wins=true`; `resource_catalog.gd:157-159`).
- To-hit is rolled once per use, before any effect; a miss skips every effect (`ability.gd:38-42`, `unit_combat.gd:367-383`).
- **Decided before shown.** `UnitCombat._decide` makes every roll in one frame: rounds fired, to-hit, rapid-fire hits, defense, and each effect's `AbilityEffect.resolve()` (dice, DR, who an area catches). Those are stored in an `AbilityAction` (`ability_action.gd`), which goes on `Unit.current_action` before `ability_use_started`. Presentation reads it and decides nothing. `commit(plan)` lands exactly what was resolved; `apply()` is `commit(resolve())` for the AI and other direct callers. Only the six dice effects split; the rest keep the default (resolve `{}`, commit = apply). Effects are shared flyweights, so per-use state lives on the action.
- **Moments come from the clip.** A cast clip's Call Method keys (`CharacterModel.release()` / `.impact()`, relayed as `CharacterModel.moment` to `UnitAnimator`) release the `AbilityAction` and land it. `AbilityAction.release()` fires once and emits `Unit.cast_released`, which starts the cast VFX and projectile (`unit_vfx.gd`); `impact()` releases first. Fallbacks, all in `unit_animator.gd`: sequence end with no key, abandoned or replaced sequence, hit reaction, death, cutscene claim, no cast animation (at once); `UnitCombat.RELEASE_TIMEOUT` (3 s) backs them all. `impact_timeout` counts from the release. Keys today: Spell_Simple_Shoot release 0.2, fireball Cast release 0.3, Jump_Start impact 0.25 (`jump.tres` waits for it), and every `Weapon/*` clip (`assets/weapon_animations.tres`, built by `tools/make_weapon_animations.gd`): melee clips carry an impact key (Swing about 0.23 s, Thrust 0.37, Claw 0.6), shooting and throwing clips a release key per shot (bow about 0.87, crossbow 0.31, throw 0.37, pistol three). Proof: `tools/ability_moments_demo.tscn`, `tools/weapon_visuals_demo.tscn`.
- **Per shot.** `AbilityAction.shots` is the rounds fired (rapid fire), else 1. Each release key lets one go (`release_next`), each starts its own `cast_vfx` (one tracer, one flash), and each projectile's ImpactSignalStep is one `impact()`. A waiting ability lands its hits one per impact, in order (`GearDamageEffect.hit_plan`); other effects land with the first. A clip with fewer keys than shots lets the rest go at its end (`release_all`). A miss waits for its impact too, then emits `Unit.defended(kind)` so the defender's dodge, parry or block plays as the shot arrives.
- **Weapon clips.** `AttackRow.motion` / `cast_vfx` replace the template's on the bound copy (`UnitCombat._bound_to`); a row without them uses the template's: `basic_attack_melee` `&"attack.swing"` and waits for impact, `basic_attack_ranged` `&"attack.shoot.crossbow"` with `bolt_flight`. Abilities, rows, weapons and statuses name motion keys, never clips; the body's `MotionSet` turns a key into a clip or sequence (see unit.md). Projectiles: `data/vfx/arrow_flight|bolt_flight|axe_throw|gunshot.tres`, scenes in `scenes/weapons/projectiles/`.
- **Always finishes.** A waiting ability lands on the first `Unit.notify_impact()` while its action is current, or at `impact_timeout` (`result.impact_timed_out`). Every path ends in `UnitCombat._finish`: `ability_used`, `action.finish()`, `current_action` cleared. If the Unit target is freed or dead after the wait, nothing lands (`result.target_lost`, no combat trigger); area commits skip freed units.
- Effects run in array order with the same `is_critical` flag (`unit_combat.gd:436-437`).
- Area effects read radius from the sibling `AreaTargeting` (`area_damage_effect.gd:41-46`); an area effect on a non-area targeting silently does nothing (`:42-43`).
- **Only one armed ability, for one unit, globally** (`ability_manager.gd:29,36`). Comment `:346-350` already notes the party can be in two worlds; the single global arm is still assumed. Not STALE yet because hotbar disarms on world focus (`ui/ability_hotbar.gd:228-232`), but it encodes "one focused world".
- `resolve_click_ability` uses `armed_ability` without checking `armed_unit == acting_unit` (`unit_combat.gd:213`); correctness relies on the hotbar disarming on every selection/turn change.

## Lifecycle
- `AbilityManager`: autoload, lives for the whole process, no save/load hooks. Disarmed on: turn start in view (`ability_hotbar.gd:116`), combat end (`:131`), out-of-combat selection change (`:170`), world focus change (`:232`), right-click (`aiming_intent.gd:47`), new game (`save_manager.gd:620`), attack action spent / move exhausted (`ability_manager.gd:126-143`). NOT on save load (`_perform_load`, `save_manager.gd:405-539`, has no disarm call); this relies on the world-focus disarm.
- `AbilityDatabase`: lazy static scan on first `find/get_all` (`ability_database.gd:50-53`); never invalidated except `refresh()`.
- Cutscene/dialogue: no handling in this system; the presentation listeners gate themselves (`unit_animator.gd:313`).
