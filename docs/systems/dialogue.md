## Purpose
Runs one player-facing conversation at a time: a `Conversation` (RefCounted) walks a tree of `DialogueNode`s compiled from `.dlg` files by DialogueScript, resolves choices (lines, skill checks, quick contests), applies effects (flags, items, combat trigger, negotiation mood/gold/pardon/outcome) and exposes a pull-model `snapshot()` to presenters. Negotiation is the same engine with `presentation = negotiation` and a different panel. It does NOT own UI layout (overlay/panel follow it), camera (asks CinematicDirector), or persistence (it has none).

## Assumptions and invariants
- Exactly one conversation process-wide (conversations.gd:24, refused if `current != null` :52). Comment at world_context.gd:22-27 calls it PLAYER-scoped, which is consistent with one focused world - but see cast below.
- `current` is cleared only when the conversation itself reports `ended` (conversations.gd:96-102). Invariant "every conversation reaches end()" is only enforced by authoring + lint; there is no external terminator.
- Cast is built tree-wide, not per world: `UnitQuery.core_party_units(tree)` (talk_interaction.gd:72 -> unit_query.gd:135-140, uses all_units :52-59, not `_in_world_of` :99-111). **STALE** single-world assumption: WorldManager keeps multiple resident worlds (world_manager.gd:1062).
- Talk refuses if any participant is in combat (talk_interaction.gd:24-29); Negotiate requires the actor IS in combat (negotiate_interaction.gd:35).
- `next_node_id` strings must match a node `id` in the same folder; unknown id at runtime = push_error + dead end (conversation.gd:389-398).
- Duplicate node ids: later file wins with a warning (dialogue_node_index.gd ~:65).
- No save during dialogue: `can_save` false in DIALOGUE/NEGOTIATION (save_manager.gd:292-302), so no save_state is needed - but LOAD is not gated (issue 1).

## Lifecycle
- **Stand-ins**: `DialogueStandIns` (dialogue_stand_ins.gd; added in main_root.gd before DialogueGaze and DialogueStaging, which work on what it raises) follows `Conversations`. On begin of a `dialogue` presentation it fits `cinematics/templates/dialogue_pair.tscn` to the cast (`npc` on the spot, `player` 1.15 m in front, facing each other) and raises a `StandIn` per role; on end it strikes them, in the frame the camera cuts back. Units are not moved or turned. When the template does not fit, nothing is raised and the talk plays on the units as they stand. Only `npc` and `player` have marks; other cast members and bystanders keep their own bodies. Negotiation raises none. See cinematics.md.
- **Lighting**: the dialogue system adds none of its own. Each unit's `CharacterLightRig` (character_light_rig.gd, owned by the Unit, built by `Unit.light_as_body`) lights it under every camera, the dialogue camera included: key, fill and rim spots with shadows, turned to whichever camera is on screen, so speaker and listener are both lit. While a `StandIn` or a `CutsceneRole` body shows the unit, the rig stands on that copy (`Unit.light_follows`, called by `StandIn.raise` and `CutsceneRole.dress`). On the patched engine (godot_patches/) a rig lights its own character alone; on stock Godot only its reach keeps it off a neighbour.. Limits: the key is always camera-left, not on the sun's side; nothing fades at the start or end of a conversation; energies are the same in a close-up as in play.
- **Faces** (owner: DialogueStaging, 2026-11-19): every spoken line is mouthed on the speaker's face (`FaceDriver.of(speaker).talk(text)`, the stand-in's when one shows the unit). A staging tag on the line that names a `FaceDriver.EXPRESSIONS` entry (`#smile`, `#frown`, `#angry`, `#surprised`, `#wary`, `#neutral`; written before the `#line:` id) is the face the speaker takes on that line, held through the rest of their run of lines. When they start speaking again after someone else, the face goes back to neutral unless that line is tagged, and every cast member's face goes back to neutral when the conversation ends. Other tags (`#close`) are ignored here. Only townsperson.dlg is tagged so far; untagged files talk with a neutral face. Player responses carry no tags, so the player always answers neutral.
- **Begin**: interaction -> `Conversations.begin` sets current, connects, emits began, `c.start()` (conversations.gd:49-60); overlay opens only for `presentation == dialogue` (dialogue_overlay.gd:124-136), negotiation panel for negotiation.
- **Step**: `choose()` awaits `choice.resolve()` (conversation.gd:141-163) which may await dice (`show()` awaits `_wait_completed`, returns immediately with no presenter :304-310); `advance()` / `complete()` :168-185.
- **End**: `end()` (conversation.gd:190-202) -> changed -> Conversations clears current, emits ended -> overlay closes.
- **Combat start** (TriggerCombatEffect): does not end the conversation; relies on authored empty next id (trigger_combat_effect.gd:12-16).
- **Travel**: blocked while a conversation runs (world_manager.gd:258-272).
- **Save**: refused. **Load / new game**: not handled (issue 1).
- **Player abort**: none - Leave/History/Settings chips are stubs (dialogue_overlay.gd:115-117, :327-328); overlay `closes_on_cancel=false` (MainRoot.tscn:369).
